# 개발 흐름 (코드 변화 기록)

파일 수정 날짜와 노션 개발 기록을 바탕으로, 펌웨어가 어떻게 바뀌어 왔는지 정리했습니다.
각 단계의 코드는 `versions/` 폴더에 남겨 두었고, 최종 코드는 `src/main.cpp`입니다.

## 단계별 변화

### 0단계: 하드웨어 기반 (2025.08 ~ 10)
- **AS5048A 저수준 드라이버**: SimpleFOC의 기본 SPI 센서 클래스로 엔코더 값이 읽히지 않았습니다. 그래서 SPI를 직접 읽는 `CustomAS5048A`를 만들고 SimpleFOC `Sensor`를 상속해 연결했습니다.
- **타이머 분리**: 두 SimpleFOC 쉴드의 PWM 핀이 같은 타이머를 써서 모터 2개가 동시에 돌지 않았습니다. 모터 B의 PWM 선을 끊고 TIM1(PA8/PA9/PA10)으로 다시 연결했습니다.
- 핀 정의를 `balancer_pinouts.h` 하나에 모았습니다. 이 파일은 이후 보드를 바꿀 때까지 한 번도 바뀌지 않았습니다.

### 1단계: 첫 밸런싱 (2026.01.12)
- MPU6050 레지스터를 직접 읽고, 가속도 LPF와 상보 필터로 roll을 계산했습니다.
- 밸런싱은 `pid_stb(P=17)` 하나로, 기울기 오차를 바로 토크(전압) 명령으로 썼습니다.
- PID 출력 포화(8V 초과)와 IMU NaN을 감지해 출력하는 디버그 코드를 넣었습니다.
- **문제**: 급격히 기울이면 로봇이 멈춰서 PID 튜닝이 제대로 되지 않았습니다.

### 1.5단계: IMU 안정화 시도 (2026.01.14)
- **burst read**: 가속도·자이로를 6번 나눠 읽던 것을 14바이트 한 번에 읽도록 바꿨습니다. I2C 통신 횟수를 줄여 멈춤을 줄이려는 목적입니다. 통신 실패 시 멈추지 않고 이전 값을 유지하게 했습니다.
- **DMP 방식**(`mpu6050v2.cpp`): MPU6050 내부 DMP가 계산한 쿼터니언으로 pitch를 얻었습니다. 값이 갑자기 크게 튀면 0.01씩만 따라가도록 해서 튀는 값을 걸렀습니다.
- **결과**: DMP로 튜닝에는 성공했지만, 값이 한 방향으로 계속 흘러가는 drift가 생겼습니다. 라이브러리 업데이트, 레지스터 게인 조정, 이중 필터로도 해결하지 못했습니다.

### 2단계: CAN 통신 단독 테스트 (2026.01.19)
- Arduino 프레임워크에는 STM32 CAN 기능이 없어서, HAL로 CAN을 직접 초기화했습니다 (500kbps, 모든 ID 수신).
- 라즈베리파이는 `python-can`으로 ID `0x100`에 throttle과 steer를 int16 2개로 보내고, STM32는 이를 받아 시리얼로 출력했습니다.
- 라즈베리파이 쪽은 STM32가 꺼져 있어도 프로그램이 죽지 않도록 전송 에러를 처리했습니다.
- **남은 문제**: CAN을 PB8/PB9에 두었는데 이 핀은 IMU의 I2C1 핀과 같습니다. 밸런싱 코드와 합치려면 핀을 옮겨야 합니다. 정리한 핀 배치는 [PINMAP.md](PINMAP.md)에 있습니다.

### 3단계: 보드와 IMU 교체 (2026.01.22 ~ 31)
- **보드 변경: F103RB → F446RE**
  - 같은 Nucleo-64 핀 배치라서 쉴드와 배선, `balancer_pinouts.h`를 그대로 썼습니다.
  - Cortex-M4F(180MHz, FPU)라서 FOC와 PID 같은 실수 연산이 빨라집니다.
  - CAN을 쉽게 쓰기 위해 `STM32_CAN` 라이브러리를 추가했습니다.
- **엔코더 통신 안정화**: AS5048A SPI 속도를 1MHz에서 500kHz로 낮추고, CS를 내린 뒤 1µs를 기다리고 읽도록 바꿨습니다.
- **IMU 변경: MPU6050 → BNO055**
  - 9축 센서이고 칩 안에서 센서 퓨전을 해서 roll/pitch drift가 거의 없습니다.
  - Adafruit 라이브러리로 초기화만 하고, 각도는 Euler pitch 레지스터(`0x1E`) 2바이트를 직접 읽습니다 (1° = 16 LSB). 라이브러리 함수보다 통신량이 적어 빠릅니다.
  - I2C 핀을 `Wire.setSCL(PB8)`, `Wire.setSDA(PB9)`로 직접 지정하고 400kHz로 올렸습니다.
- **제어 변경**
  - `pid_stb`를 P=17에서 PID(30, 100, 1), 출력 제한 8V로 바꿨습니다.
  - 센서 장착 방향에 맞춰 PID 출력 부호를 반대로 했습니다.
  - 전원 전압 설정을 12V에서 10V로 낮췄습니다.
  - IMU를 2ms마다 읽고, 읽기에 실패하면(-999) 그 주기는 건너뛰도록 했습니다.
  - 속도 PID(`pid_vel`) 계산을 넣었지만, 아직 기울기 목표값에는 연결하지 않았습니다.

### 4단계: 캐스케이드 제어 (2026.02.01, 최종)
- **캐스케이드 PID 적용**: 바깥 루프가 바퀴 속도를 보고 목표 기울기를 정하고, 안쪽 루프가 그 기울기를 따라갑니다.

```
바퀴 평균 속도 = (모터1 속도 + 모터2 속도) / 2
목표 기울기 = LPF( pid_vel(바퀴 평균 속도 − LPF(throttle)) ) + 0.045
토크 명령   = −pid_stb(목표 기울기 − 현재 기울기)
모터1 = 토크 명령 + LPF(steering)
모터2 = 토크 명령 − LPF(steering)
```

- 기울기만 맞추면 로봇이 한쪽으로 계속 굴러갈 수 있습니다. 속도 루프가 이를 잡아서 제자리에 서 있게 해 줍니다. `throttle` 값을 주면 그 속도로 앞뒤로 움직일 수 있습니다.
- `+0.045 rad`(약 2.6°)는 로봇 무게중심이 앞뒤로 치우친 만큼을 보정하는 값입니다.
- throttle과 steering에 LPF를 걸어, 나중에 CAN으로 들어올 주행 명령이 급하게 바뀌어도 부드럽게 반영되도록 했습니다.
